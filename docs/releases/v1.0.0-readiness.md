# v1.0.0 release readiness

This is the gate list for a fictional-data v1.0.0 release. MatterHarbor remains a portfolio and learning project. Passing these gates does not authorize real personal data or establish production readiness; those claims require a separate review.

The release is **not ready** until every gate below has evidence from the release candidate commit.

- [ ] Role-aware case creation, assignment, and status changes reject unauthorized members and keep every query scoped to the authenticated organization. Cover allowed and denied paths through hosted HTTP tests.
- [ ] Every case mutation uses an explicit concurrency and retry contract and writes its audit record atomically. Verify replay, conflict, and concurrent requests against PostgreSQL.
- [ ] The worker has bounded retry backoff, a dead-letter path with reviewed redrive steps, retention, and telemetry. Verify failure and recovery against PostgreSQL and the Azure Service Bus adapter contract.
- [ ] An approved, serialized deployment pipeline applies a checksummed migration bundle with a migration-only identity before starting the matching application images. Exercise the pipeline in a disposable environment with restricted runtime database roles.
- [ ] A backup and restore exercise preserves fictional v0.1 data, validates the restored migration head and case reads, and records the recovery procedure and result.
- [ ] The README release checks and unskipped full-stack Playwright flow pass at the release candidate commit. Security scans have no unresolved high-severity findings.
- [ ] Update the changelog, roadmap, product specification, threat model, version, and v1.0.0 release notes to describe only verified behavior.

Do not create the v1.0.0 tag or publish release notes while any box remains open.
